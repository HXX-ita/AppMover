## 逐条对应目标要求

### 1. 扫描 C 盘中的软件与数据文件夹

| | |
|---|---|
| 实现 | `Core/Scanner.cs`（标准位置枚举）、`Core/TreeWalker.cs`（容错统计）、`Core/SoftwareIndex.cs`（注册表卸载项 + 服务索引） |

| 交叉验证 | 与独立的 PowerShell 引擎逐条比对：条目数 288 vs 287，差异唯一且已知（刻意的系统目录跳过） |

| | |

### 3. 选中后弹出确认窗口

| | |
|---|---|
| 实现 | `Gui/ConfirmDialog.cs` |
| 内容 | 源路径、目标位置、大小、目标盘可用空间变化、**判定依据**、**要关闭哪些程序**、**风险提示**、将要执行的六步操作、搬移后的注意事项 |
| 安全设计 | 必须勾选确认才能点"开始搬移"；**有阻止项时只给关闭按钮，不给强行继续** |

### 4. 在目标盘创建同名文件夹并迁移

| | |
|---|---|
| 实现 | `Core/Relocator.cs`：目标 = `<目标盘根>\<源目录名>` |
| 证据 | 真实软件实测：`AppData\Local\Programs\Python` → **`D:\Python`**（同名新家） |
| 盘符形式 | 界面传的目标盘是 `D:\` 这种带尾部分隔符的形式，已有专门的 9 项断言守住 |

### 5. 用「复制-校验-删除-建目录联接」保证软件仍可用

| | |
|---|---|
| 实现 | `Core/Copier.cs`（robocopy + 数量/字节/抽样 SHA256 校验）、`Core/Junction.cs`（`FSCTL_SET_REPARSE_POINT`，不经 `cmd /c mklink`）、`Core/SafeDelete.cs`（缓存删除时不递归进联接） |
| 顺序改进 | 实际实现是「复制 → 校验 → **改名让位** → 建联接 → 验联接 → 删旧」。删除源不可逆而建联接可能失败，把不可逆步骤夹在两个可逆步骤之间，**全程不存在同时失去两份数据的时刻** |
| 真实证据 | Python 3.10.11（96.10 MB / 5484 文件）搬移后：版本 ✓、计算 ✓、标准库 ✓、第三方包 6 个 ✓、**pip 可用且仍报告原路径** |
| 系统层证据 | `fsutil reparsepoint query` → 重解析标签 **`0xa0000003`（Mount Point）**；PowerShell → `LinkType: Junction` |
| 空间证据 | C 盘 62.23 → **62.32 GB**，D 盘 476.21 → **476.11 GB** |

### 6. 可回退的撤销记录

| | |
|---|---|
| 实现 | `Core/Journal.cs`（JSON Lines 日志）+ `Relocator.Undo` |
| 拒绝路径 | 状态不符 / 目标不在 / 原位不是联接 / 联接指向别处 —— **四种现场全部拒绝，且拒绝后磁盘未变**（13 项断言） |
| 真实证据 | 在同一个 Python 上执行撤销：5484 文件 / 100765335 字节与基线**完全一致**，五项功能检查全通过，D 盘可用空间精确回到 **476.21 GB**，日志状态变 `reverted` |
| 记录可追溯 | `journal.jsonl` 保留完整两条记录（一撤一搬），字段 `junctionCreated` 经修复后正确写入 |

### 7. 能搬 / 不能搬 / 疑似残留垃圾三类判定严谨且有据可查

| | |
|---|---|
| 实现 | `Core/Classifier.cs`（两张规则表 + 位置分类）、`Core/CloudSync.cs` |

| 规则怎么来的 | 先在真实机器扫描，再**逐条人工审计输出**，修掉三类系统性误判才定稿（详见 README 的"规则是怎么定出来的"） |
| 本机实扫结果 | 共 **287 个目录**：禁止搬移 80 项/33.35 GB、可安全搬移 131 项/29.24 GB、可搬但需小心 65 项/17.58 GB、疑似残留 11 项/2.53 GB |
| 独立交叉验证 | 与 PowerShell 引擎的 8 项差异全部可解释，且**均为 C# 侧有意的规则改进** |

### 8. 明确所需权限与提权方式

| | |

### 9. 处理多磁盘与空间不足

| | |
|---|---|
| 实现 | `Core/Volumes.cs`（枚举固定 NTFS 卷、判断是否能承载联接）、`Relocator.HasEnoughSpace` |

### 10. 文件被占用等异常

| | |
|---|---|
| 实现 | `Core/Occupancy.cs`（Windows Restart Manager：`RmStartSession` / `RmRegisterResources` / `RmGetList`） |
| 行为 | 预检阶段列出占用该目录的进程，并要求用户先关闭；确认窗口里展示 |
| 证据 | 4 项断言：未锁定不误报、独占锁定能报出、**报出的 PID 就是持有文件的进程**、释放后不再报 |
| 为什么必须测 | 这套 P/Invoke 接线若写错不会报错，只会**永远返回"没占用"**，用户拿不到提示 |

## 已知限制（如实列出）

1. **只支持 Windows，且只支持系统装在 C 盘。** 这是有意的范围收敛。
2. **没有做目标盘在搬移过程中被拔掉的集成测试。** 相关代码路径存在（复制失败即回滚），但未构造该场景。
3. **没有做磁盘写满的集成测试。** 只有两块大盘，无法制造空间耗尽；已通过单元测试覆盖规则本身。
4. **兼容性清单尚薄。** 只在 Python 3.10.11 这一个真实软件上完整验证过。VS Code、游戏启动器、通义千问等已扫描但未实测搬移。
5. **界面未经人工视觉检查。** 几何断言能证明控件不重叠、不越界、状态正确，但证明不了字体协调、间距舒适、中文无截断。
6. **未做代码签名。** 用户首次运行可能被 SmartScreen 提示。
7. **CI 尚未真实运行过**（因为还没推送）。

## 结论
