# 软件搬家 · AppMover

把 C 盘上的软件和数据文件夹搬到别的盘，**搬完软件照常能用**。

只支持 Windows 10 / 11。免安装，不用装任何运行库。

---

## 下载和运行

1. 打开 [Releases 页面](https://github.com/HXX-ita/AppMover/releases)，下载
   **`AppMover-x.y.z-win-x64.zip`**
2. 解压到任意一个文件夹（例如 `D:\AppMover`）
3. 双击里面的 **`AppMover.exe`**

> ⚠️ **别下成 "Source code (zip)"。** 那是源代码，不是程序。
> 认准文件名里带 `win-x64` 的那个。

解压出来的文件夹长这样，程序就在最外层：

```
AppMover.exe          ← 双击这个
AppMover.exe.config
AppMover-cli.exe      命令行版（一般用不到）
AppMover-cli.exe.config
feedback.html
feedback.json
README.md
README.en.md
LICENSE
```

> 如果你是从源码自己编译的，程序在 `build\` 子目录里（`build\AppMover.exe`）。
> 发布包里**没有** `build` 文件夹，程序直接放在最外层。

## 界面怎么操作

1. **选目标盘** —— 默认自动选中空闲最大的非系统盘，也可以自己改
2. **点「开始扫描」** —— 等它列出 C 盘上的目录，每一项都带分类和判定依据
3. **选中一项 → 点「搬移选中项」**（或双击那一项）
4. **在弹出的确认窗口里看清风险和前置动作**，勾选确认，才会开始搬
5. 搬完不满意，到 **「历史记录与撤销」** 页一键撤销，文件会原样回到 C 盘

**有一个文件夹就要确认一次，没有"一键全搬"** —— 这是故意的。

## 四种分类

| 颜色 | 含义 | 怎么办 |
|---|---|---|
| 🟢 可安全搬移 | 数据目录、缓存、便携软件 | 放心搬 |
| 🟠 可搬但需小心 | `Program Files` 下的已安装软件、带服务的、有自动更新的 | 看清确认窗口里的提示再搬 |
| 🔴 禁止搬移 | Windows 本体、共享组件、驱动、商店应用、卸载信息 | 程序不允许搬 |
| 🟣 疑似残留可清理 | 缓存和安装器残留 | **只提示，绝不自动删**，要不要清你自己定 |

每一项都会告诉你**为什么**这么判，不是只丢一个结论。

---

## 原理（一句话）

搬移的做法是：

```
复制到目标盘 → 校验一致 → 删除原目录 → 在原位置建立「目录联接」
```

目录联接（junction）对软件是透明的：程序访问 `C:\Program Files\Foo\x.dll` 时，
文件系统会把它转到 `D:\Foo\x.dll`，而**路径字符串本身没变**。
注册表、快捷方式、服务配置里记的都是老路径，所以照常能用。

## 需要管理员权限的情况

| 做什么 | 需要 |
|---|---|
| 扫描 | 普通用户 |
| 搬 `AppData`、用户目录 | 普通用户 |
| 搬 `Program Files` / `ProgramData` | **管理员** |
| 停 / 起服务 | **管理员** |

需要的时候程序会明确弹窗申请，不会偷偷提权。

## 安全上的几条底线

- **校验没通过之前，绝不删源目录**；任何一步失败都回到"原目录还能用"
- 每个文件夹单独确认
- 全程写撤销日志，随时能搬回去
- 有干跑模式：只出计划，不动文件
- 断电或崩溃中断了搬移，用 `recover` 命令修复

## 命令行（进阶 / 排错）

用 `AppMover-cli.exe`（和界面共享同一套内核）：

```
volumes                列出所有卷，以及能不能当搬移目标
rules                  打印判定规则表
tree <路径>            统计目录大小和文件数
classify <路径>        对单个目录给出分类和依据
scan [--json 文件]     扫描标准位置并分类，输出摘要
plan <路径>            规划一次搬移（只读，不改任何文件）
move <路径>            执行搬移
journal                查看搬移记录（撤销要用记录号）
undo <记录号>          撤销一次已完成的搬移
recover                修复被中断的搬移
                       --restore <记录号> 还原，--complete <记录号> 做完
feedback               生成脱敏诊断报告，并给出填好的反馈链接
selftest               内置自检（173 项）
```

`plan` / `move` 的选项：`--to D:\`、`--dry-run`、`--allow-same-volume`、`--force`

## 常见问题

**杀毒软件报毒？**
程序会做复制、建目录联接、删目录这些系统级操作，行为上确实像"危险工具"。
源码全在这个仓库里，可以自己编译核对。加白名单即可。

**搬完软件打不开了怎么办？**
到「历史记录与撤销」里撤销，文件会回到原位。撤销是搬移的逆操作，同样会校验。

**能搬 Windows 目录或驱动吗？**
不能，程序会直接拒绝。这类目录搬了系统会坏。

**搬完 C 盘真的空出来了吗？**
空出来了，但原位置会留下一个目录联接（体积极小，只占几十字节）。删掉它软件就找不到了。

**为什么是两个 exe？**
`WinExe` 子系统不会附着到父进程的控制台，命令行输出会丢。合成一个二进制要手工
`AttachConsole` 并重开 stdout，脆弱且难测。两个可执行文件共享同一份内核更稳。

## 从源码构建

需要 Windows 自带的 `csc.exe`（.NET Framework 4.8 自带，**不需要装 .NET SDK**）。

```powershell
git clone https://github.com/HXX-ita/AppMover.git
cd AppMover
powershell -ExecutionPolicy Bypass -File src\build.ps1
# 产物在 build\ 目录：build\AppMover.exe / build\AppMover-cli.exe
```

跑自检：

```powershell
build\AppMover-cli.exe selftest
```
